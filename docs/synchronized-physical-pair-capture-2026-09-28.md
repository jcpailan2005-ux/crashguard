# Synchronized Physical-Pair Capture

## Existing support audit — before implementation

The existing opt-in `backend/services/live_collision_diagnostics.py` records decision metadata, detections, qualification, and streaks. Its `Observation` receives an observation sequence and frame receive time but **never receives or writes the image frame**. Its rotating JSONL has no field that can link an observation to saved pixels. The active worker copies the native decoded frame under its lock at the start of `_analyze_current_frame`, then uses that same local frame for quality analysis, model inference, vehicle extraction, and the final decision. Existing `save_detection_snapshot()` is reached only for selected case/duplicate paths, not for ordinary completed decisions. During the previous reproduction it saved no post-baseline collision images. Browser preview sampling is asynchronous and cannot be equated to the exact decision frame.

**EXISTING_CAPTURE_SUPPORT_NOT_SYNCHRONIZED.** An additive opt-in diagnostic hook at the live worker's local frame is necessary to preserve pixels with the already recorded decision sequence. The change must keep the existing decision inputs and control flow intact, move disk writes off the inference thread, bound memory/disk/time, and remain OFF by default.

## Diagnostic-only implementation

The existing `LIVE_COLLISION_DIAGNOSTICS=1` opt-in still controls the metadata collector. A second opt-in, `LIVE_COLLISION_FRAME_CAPTURE=1`, asks that collector to freeze the native BGR image at the worker's existing `begin` point. Both exact values `1` are required; default is OFF. The frame is copied immediately after the worker releases its capture lock, before quality analysis and model calls. It is the exact local image supplied as `detection_frame` to inference. No separate preview sample or second camera read is involved.

At the existing decision boundary, the collector submits one immutable frame reference plus the completed observation metadata to a separate queue of at most **8** items. A daemon writer saves a lossless, uncompressed NumPy `.npy` frame, computes SHA-256 of its file bytes, then appends a copy of the full diagnostic row with `frame_file`, `frame_sha256`, shape/dtype, frame bytes, writer duration, and capture status to the session's `observations.jsonl`. The observation ID, decision timestamp, camera ID, detection proposals, accepted vehicles, evaluated pairs, qualification, and streak all come from that same decision record. The per-session `manifest.json` counts saved frames, bytes, drops, errors, and latest observation. The existing rotating metadata-only JSONL remains available.

The session is created lazily under `backend/validation/live_collision_diagnostics/physical_pair_capture_<UTC start>_<run ID>/`, with `frames/`, `observations.jsonl`, and `manifest.json`. Limits are **1,200 frames**, **3 GiB frame bytes**, **15 minutes from the first decision**, and the eight-item queue. Exceeding a bound drops diagnostic frame submissions without changing collision decisions. The uncompressed image is exact BGR pixel data; its `.npy` header contains only shape and dtype. Abrupt process exit may lose queued diagnostic rows, so a finished session needs file/hash/count validation before analysis.

The writer performs file creation, lossless serialization, hashing, JSONL append, and manifest update outside the live inference and capture locks. The inference thread makes one memory copy when both flags are ON. `frame_snapshot_copy_ms`, `frame_save_duration_ms`, inference duration, observation interval, and diagnostic drop/error counters permit measured overhead review.

Changed files: `backend/main.py` (one diagnostic emit of the existing local frame), `backend/services/live_collision_diagnostics.py` (bounded synchronized sink and frame copy), `backend/tests/test_live_collision_diagnostics.py` (equivalence and image/hash/queue tests), `.gitignore` (exclude generated session folders containing camera imagery), and this report. No collision threshold, streak, model call, ROI, pair geometry, persistence, or alarm branch was changed.

Targeted tests: **19 passed**. They verify OFF/ON decisions and inference-call counts match for deterministic observations; frame capture ON preserves the same decision results and sequence; the writer saves a lossless frame with the corresponding JSON row and valid SHA-256; queue capacity remains bounded. This establishes decision equivalence for tested inputs, not zero live overhead.

The synchronized writer incremented `diagnostic_write_errors` only in its broad `_run()` exception handler. That handler covers metadata parsing, directory creation, lossless NumPy frame write, stat, hash, frame rename, row serialization/JSONL append, and manifest temp write/rename. It previously discarded the exception and stage, so the two historical errors cannot be attributed to one operation from the available evidence. Queue-full and capture-limit paths increment the separate drop counter. The metadata-only rotating sink has its own error counter and is not the synchronized writer's manifest counter.

A minimal diagnostic-only visibility change now writes at most 32 `writer_errors.jsonl` entries per session, with UTC time, observation sequence, fixed stage label, exception type, numeric errno/WinError, and a generic OS error message. It never serializes arbitrary exception text, file paths, frame data, URLs, or credentials. If even the error log cannot be written, that failure remains isolated from production decisions. The stage labels distinguish frame write/stat/hash/rename, JSONL append, and manifest temp write/rename. No collision decision code was changed.
